# Current build additions — 0.8.0

Metadata work is keyed by canonical document URI, with subscribers per mint. `wantMeta(t, {priority:true})` promotes queued and active work; visible metadata races both available hosts immediately. Successful public fields are bounded, sanitized and cached under `nought.metadata.v1`; no wallet data is stored there. A stale response cannot apply to a changed URI. See CHANGELOG.md and the 0.8 section in QA.md for bounds and verification.

The source is published at https://github.com/PiccoloNiccolo/nought. Dated notes below describe earlier releases. `dist/` is generated and ignored by Git; run `npm run build` before `npm run preview` on a fresh clone.

# 0.2 implementation notes (2026-10-04)

This copy lives in the current Codex chat and supersedes the historical freeze/ownership notes below. It is still static, original, and zero-house-fee.

- `app.js` starts SOL pricing and Pulse seeding independently.
- `seed.js`: gems/recent intervals are 4/10 seconds on Pulse, 30/60 seconds on other pages, paused while hidden. `feedCadence()` exports the policy; `feed` events report status without dirtying stored tokens.
- `stream.js`: one poll per watched mint every 5.5 seconds; `TradeCursor` pages to overlap, at most four pages per pass, retaining progress after a failed request. Up to 6,000 pending/seen trades per coin; excess/repeated cursors produce a visible delayed-feed error. `tradeState(mint)` returns status. Trade events include provider `id`.
- `jup.js`: persistent provider failures back off 10–120 seconds plus jitter, or longer when Retry-After asks. GETs try the alternate host after a 3.5-second first-host timeout. `ju.holdings` retains numeric `accounts` and adds validated `tokenAccounts` records for withdrawal source selection.
- `fee-policy.js` rejects integrator fee/referral/builder parameters in transport and nonzero platform fees in standard quotes. Provider fees in protected execution remain separately disclosed.
- `store.saveBoard()` writes only dirty state. `LS.set()` returns a boolean, evicts the board cache on critical-write quota pressure, and emits `storage-error` if a critical write fails.
- `orders.js` requires successful read-back of armed state and Web Locks before a claim can trade. No claim persists, no trade is attempted.
- `cardKey()` skips rebuilding unchanged Pulse card HTML. Trades retain unchanged rows. Per-history trade cache: 6,000; capped history is never labelled complete.
- Alerts emit `alerts-quotes` for changed prices, `alerts-list` for list changes. Portfolio uses the shared Hyperliquid budget. All age counters pause while hidden.
- CSP permits pinned library scripts and blocks inline JavaScript. Theme initialization is a same-origin file.
- `tools/build.mjs` emits a static `dist/` plus integrity manifest and compressed assets. Do not place API secrets in public source; premium shared credentials require a server architecture.

# Nought build contract (read before touching code)

Nought is an ORIGINAL open-source, zero-fee Solana memecoin terminal in the dense dark style of trading terminals like Axiom. Feature parity is the goal; copying is not.

## Hard rules
1. **Original work only.** Never copy Axiom's (or anyone's) code, text, logo, icons, names of their features in their exact branding, or screenshots. Write all UI copy yourself. Our name is Nought, our mark is the "0" ring with a slash.
2. **Zero fees.** Never pass `platformFeeBps`, `feeAccount`, `feeBps` or a referral/builder code to Jupiter, Trigger or Hyperliquid. Every trade UI shows "Nought fee 0%" and lists third-party costs (pool/pump.fun fees, network, priority, tips) separately.
3. **No backend, no secrets.** Static files only. Never embed API keys. Only use CORS-open keyless endpoints (see `docs/feature-matrix.md` §0, §17). Never use `api.mainnet-beta.solana.com` or `frontend-api*.pump.fun` (CORS-blocked).
4. **Untrusted data.** Every string from a token, wallet, or API goes through `esc()` before HTML and `safeUrl()` before any href/src (`src/core/util.js`). Never `innerHTML` raw API strings. Never `eval`.
5. **Money safety.** Transactions only come from Jupiter (swap/ultra/trigger) or code you build with `@solana/web3.js` for transfers the user explicitly asks for. Show amount, destination and token before any signing. Never send funds anywhere the user didn't type or pick.
6. **Own your files.** Only edit files assigned to you. Shared core files are frozen after the core phase; if you need more from core, write a helper in your own module. `index.html`, `app.js`, `style.css` and `src/ui/shell.js` belong to the shell owner.
7. **Don't deploy, don't publish, don't create accounts or repos.**

## Core API (src/core)
Final exports after the core phase (2026-10-04). Core files are frozen now: build on these, and if you need more, write a helper in your own module. Adapters queue and rate-limit themselves and throw on network/HTTP/shape errors, so always `try/catch` and show a fallback. Call them rather than fetching Jupiter/Dexscreener yourself (their per-host queues keep us under the free limits).

**Events** (`on(evt, fn)` returns an unsubscribe: call it in your page cleanup). `tokens` (store changed, throttled ~300 ms) · `new-token` (token) · `migrate` (token) · `trade` `{mint, side, sol, tokens, usd, mcUsd, mcSol, wallet, sig, at (ms), pool, mev, tags[], backfill}` (only for mints passed to `watchTrades`; `backfill: true` on the first page) · `stream` (socket state) · `sol` (price) · `settings` · `route` · `wallet` (the `wallet` object) · `vault` `{unlocked, count, removed?, erased?}` · `traded` `{mint, side, sig, status: 'ok'|'failed'|'unknown', owner}` · `orders` `{type: 'limit'|'armed', action?: 'create'|'cancel'|'closed', ...}` · `watch` `{mint, watched, list[], external?}` (watchlist.js) · `tracker-trade` / `tracker-status` (logs.js) · from the shell: `theme` `{name, accent, colors: {bg, panel, panel2, line, line2, fg, muted, dim, accent, up, down, warn}}` (recolor canvas charts on it), `ticker` (bool), `pnlwidget` (bool), `hotkeys` (binding map). There is no `account-trade` event any more.

**Queue priority.** Every jup.js adapter takes an optional last argument `{prio: 'high' | 'normal' | 'low'}` (`jx.txs` and `jc.chart` take `prio` in their options object). `high` = a trade is waiting on it (quotes, the balance check before a sell, building a transaction), `normal` = what the user just opened (the default), `low` = background polling (`jt.recent` and `jg.gems` default to it). Each host queue drops a request that waited over 10 s or that can't start before a 429 cool-down ends, with a clear error, so nothing piles up behind a rate limit.
